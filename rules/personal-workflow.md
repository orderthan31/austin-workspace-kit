# 개인 작업 규칙

## Common

- 답변, 계획, 작업 목록, 커밋 메시지는 쉬운 한국어로 작성한다. 외부 규격·공개 API·코드 식별자는 원문을 유지한다.
- 날짜와 시각은 기본적으로 KST를 사용한다. 상대 시각 표현 대신 절대 날짜를 쓴다.
- 작업 전 프로젝트 규칙과 현재 상태를 확인한다. 사용자 확정, 제안, 코드에서 확인한 동작과 실제 검증 결과를 구분한다.
- 요청에 맞는 범위만 수정한다. 기존 변경과 다른 사람 작업을 보존하고, 커밋 요청을 받으면 관련 변경만 스테이징한다.
- 문제가 생기면 최초 실패 조건을 찾고, 가능한 검증을 끝낸다. 테스트, 커밋, 푸시, 배포는 확인한 단계별로 보고한다.
- 공통으로 재사용할 규칙은 이 저장소의 원본에서 관리한다. 프로젝트에서 필요한 추가 규칙은 해당 프로젝트의 `docs/rules/`에 둔다.

## Special

- 브랜치, 배포, 업무 데이터, 외부 도구 사용 조건은 해당 프로젝트의 규칙과 사용자 지시를 따른다.
