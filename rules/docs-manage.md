# 프로젝트 문서 관리 규칙

## Common

### 1. 문서 배치

- `AGENTS.md`는 작업 규칙 인덱스인 `docs/rules/README.md`를 안내한다.
- `docs/templates/`에 채우기 전 양식을, `docs/plans/`에 현재 계획과 상태를 둔다.
- `docs/references/high/`, `medium/`, `low/`는 현재 참고자료를 중요도에 따라 담는다. 대체된 자료는 필요할 때 `archive/`에 보관한다.
- 규칙에는 공통 원칙을 담는 `Common`과 프로젝트별 적용 기준을 담는 `Special`을 둔다.

### 2. 형식과 정본

- 새 문서가 필요하면 같은 목적의 문서가 있는지 먼저 확인한다. 기획·설계·정책·기술 검토는 Markdown을 기본으로 한다. 표 데이터에 정렬·필터·수식·집계가 필요하면 스프레드시트를 쓴다.
- 주제마다 정본을 하나 정하고 다른 문서는 정본을 링크한다. 결정이 바뀌면 현재 정본과 관련 일감도 함께 갱신한다.
- 외부 문서는 같은 파일 ID에서 필요한 부분만 수정한다. 반영 전에 최신 내용을 읽고, 반영 후 다시 확인한다.
- 회의 원문과 요약, 승인된 결정과 제안, 현재 구현과 검증 결과를 구분한다.

### 3. 계획과 참고자료

| 경로 | 기록할 내용 |
| --- | --- |
| `docs/plans/specs.md` | 확정된 기능·업무 정책 |
| `docs/plans/design.md` | 화면 판단 기준 |
| `docs/plans/architect.md` | 현재 시스템 구조와 모듈 경계 |
| `docs/plans/ideation.md` | 미확정 질문과 대안 |
| `docs/references/` | 원본 출처, 검증 근거, 과거 기록 |

- 에이전트가 주고받는 임시 요청과 보고서는 임시 위치에 둔다. 최종 결정과 필요한 근거를 정본에 반영한 뒤, 참조가 끊기지 않는지 확인하고 사용이 끝난 자료를 정리한다.
- 사용자 요청으로 인계할 때 [인계 템플릿](../templates/handoff.md)을 사용한다. 인계본 경로는 `docs/references/handoff.md`이고, 이어받는 작업자는 읽은 뒤 지속할 내용을 정본에 반영하고 정리한다.

### 4. 진행 계획 관리

- `docs/plans/sprint.md`는 현재 기간의 일감과 상태, `docs/plans/tasks.md`는 미배정 작업을 관리한다. 한 카드 ID는 두 활성 파일 중 한 곳에 둔다.
- 완료 기준은 결과를 확인할 수 있게 적는다. 카드가 끝났으면 검증 근거를 남긴다. 이월할 카드는 같은 ID를 유지하고, 지난 기간 기록은 `docs/references/archive/sprints/`에 보관한다.
- [스프린트](../templates/sprint.md)와 [백로그](../templates/tasks.md) 양식을 사용한다. 실제 사용 중인 보드가 있다면 해당 보드의 상태·상위 관계·표 구조와 일치시킨다.

## Special

- Jira·Herdr를 사용하는 프로젝트는 실제 Jira 이슈 키와 제목을 사용한다. 이슈 본문의 완료 체크리스트를 로컬 하위 카드와 연결한다. Jira 전환 및 스프린트 편성은 사용자 승인 범위를 따른다.
- 공유 문서, 개인 문서, 하위 프로젝트 문서의 소유와 링크 범위는 각 프로젝트 규칙에 적는다.
