# Herdr 연결 규칙

## 우선순위와 읽을 파일

- 사용자 지시와 프로젝트 규칙을 먼저 따른다. 원본의 자율 실행·PR 생성·메시지 전송 지시는 사용자에게서 받은 범위를 넓히지 않는다.
- 답변·작업 목록·단계명·커밋 메시지는 한국어, 기록 시각은 KST로 쓴다. 원본의 단계는 뜻을 유지해 한국어로 옮긴다.
- 원본 pstack의 `<pstack>`은 이 스킬의 `vendor/pstack/`이다. 하위 스킬 호출은 그 아래 `skills/<이름>/SKILL.md`를 직접 읽는 것으로 실행한다. 원본 파일을 기준으로 상대 링크를 해석한다.
- `create-skill`은 현재 환경의 `skill-creator`를 사용한다. `deslop`·`control-cli`·`control-ui`는 `vendor/cursor-team-kit/skills/`에서 읽는다.
- 새 커스텀 스킬을 만들거나 이 연결 규칙을 고칠 때는 Austin Skills 원본에서 작업하고 동기화한다. `vendor/`는 고정한 외부 배포본이며 직접 고치지 않는다.

## 시작 확인

세션에서 처음 Herdr를 쓸 때 `herdr-app --skill`과 `hc --skill`을 읽는다. `hc ls --json`으로 코어 연결과 실행 중 터미널을 확인한다. 화면 배치가 필요하면 `herdr-app ls`·`status`·`commands`도 확인한다.

`HERDR_ENV=1`과 구형 `herdr` CLI는 사용하지 않는다. `HC_TERMINAL_ID`는 터미널 주소이며 패널 ID가 아니다. `codex --no-daemon`으로 실행된 현재 터미널인지 실제 목록과 대조한다. 불확실한 주소로 보고 메시지를 보내거나 분할하지 않는다.

안티그래비티는 2026-11-05 KST 사용자 지시에 따라 항상 `agy --dangerously-skip-permissions`로 실행한다. 직접 호출·`hc run`·앱의 `argv`로 실행할 때 모두 같은 옵션을 붙인다.

연결이 거절되면 오류와 차단 범위를 보고한다. 실행을 다른 도구에 몰래 옮기지 않는다. 독립적으로 가능한 분석은 계속하되 다중 모델 검증을 마쳤다고 보고하지 않는다.

## 모델과 역할

원본의 `Task`·`Agent`는 아래 Herdr 위임으로 실행한다. Cursor 모델 이름을 CLI 옵션으로 그대로 넘기지 않는다.

| 원본 역할 | 기본 실행 방식 |
| --- | --- |
| 총괄·최종 판단·취합 | 현재 요청을 받은 에이전트 |
| 단일 조사 위임 | `--role investigate` · [모델 설정](../config/model-routes.json)의 `routes.investigate` |
| 구현 위임 | `--role implement` · [모델 설정](../config/model-routes.json)의 `routes.implement` |
| `arena runners`, `architect runners`, `interrogate reviewers` | Claude Code와 안티그래비티에 같은 요청을 각각 전달 |
| `how explorer`, `why investigators`, `swarm workers` | 범위를 나눠 Claude Code·안티그래비티에 배분 |
| `how explainer`, `why synthesizer` | 총괄이 탐색 결과를 읽고 Claude Code에 설명 초안 위임 후 검토 |
| `arena cross-judge pool` | 총괄·후보와 실제로 다른 모델 계열이 확인된 실행 담당 1명. 없으면 교차 심사를 생략했다고 명시 |

직접 위임에서 모델을 지정하지 않으면 각 CLI의 현재 기본값을 유지한다. 안티그래비티가 Claude 모델을 쓰면 두 실행이 같은 계열일 수 있다. 결과에는 확인된 실제 모델만 적고, 확인하지 못하면 `기본 모델·계열 미확인`이라고 쓴다. 서로 다른 모델이 확인되지 않은 리뷰는 독립 실행 리뷰로 표시한다.

사용자가 모델 구성을 요청하면 `agy models` 등 현재 CLI의 지원 목록·실제 세션 정보로 사용 가능 여부를 확인한다. 확인된 모델만 직접 위임의 `--model`·`--effort`로 전달한다. 모델이 거절되면 같은 거절값으로 재시도하지 않고 기본 모델 사용 또는 역할 생략을 명시한다. 전역 모델 설정은 바꾸지 않는다.

### 할당량 조회와 대체 실행

- 모델을 추가·교체할 때는 Austin Skills 원본의 [모델 설정](../config/model-routes.json)에서 역할별 배열을 우선순위 순서로 편집한다. `model`에는 확인한 CLI 모델 이름을 적고 Codex 기본 설정은 `null`로 둔다. 안티그래비티 모델을 추가하면 `antigravity_quota_groups`에 내장 `/usage` 결과의 모델 그룹 이름도 등록한다. 변경 파일 해시를 `manifest.json`에 반영하고 `scripts/sync_project.py`로 적용한다.
- 작업을 맡기기 전에 작업 폴더에서 `python3 /절대경로/poteto-mode/scripts/quota.py`를 실행한다. Claude Code와 안티그래비티의 내장 `/usage`, Codex의 `account/rateLimits/read`를 동시에 조회해 확인한 한도별 남은 비율을 반환한다. Claude Code 조회에는 `expect`가 필요하다.
- 이번 작업에서 조회한 JSON을 임시 파일로 보관해 `--quota`로 재사용할 수 있다. 생략하면 위임 시점에 다시 조회한다. 시간이 지났거나 한도 리셋 시각을 넘겼으면 새로 조회한다.
- `--role`은 모델 설정에 나열된 순서대로 후보를 확인한다. 한도가 소진된 실행 후보는 건너뛴다. 안티그래비티 모델은 공통 Gemini 한도와 해당 모델 전용 한도를 함께 확인한다. Codex는 일반 사용 차단 응답을 반영한다. 응답이 없거나 해석할 수 없는 한도는 `확인 필요`로 표시하고 설정 순서대로 시도한다.
- 실행 도중 한도 도달이 확인되면 총괄이 기존 실행의 종료 또는 중단을 확인한다. 구현이 진행됐다면 남은 변경과 검증 결과를 확인하고 남은 작업만 새 요청 파일에 적는다. 같은 `--role`로 다시 실행한다. 안티그래비티 모델만 거절되면 `--skip <모델 이름>`을, 도구 전체가 막히면 `--skip <실행 도구>`를 쓴다. 여러 번 걸렸으면 `--skip`을 누적하고 새 실행 이름과 결과 경로를 쓴다.
- 월별 조직 지출 한도는 조회 표에 없을 수 있다. 실제 거절 메시지를 확인하면 해당 도구를 제외한다. 권한·인증 오류와 단순 시간 초과는 따로 원인을 확인한다. 후보가 모두 소진되면 총괄이 멈춘 단계와 후보별 상태를 보고한다.

## 작업 위임

총괄은 현재 요청을 분석해 필요한 범위만 위임한다. `arena`의 후보는 같은 요청과 서로 다른 출력 위치를 받고, `swarm`의 작업자는 서로 겹치지 않는 범위를 받는다.

위임할 요청은 UTF-8 파일로 쓴다. 요청에는 목적, 읽을 절대 경로, 담당 범위, 허용된 변경, 검증할 동작, 결과 파일의 절대 경로를 포함한다. 총괄이 아닌 자식에게 전체 작업 절차를 다시 맡기지 않는다.

```bash
python3 /절대경로/poteto-mode/scripts/delegate.py \
  --role investigate --name research-a \
  --cwd /프로젝트/절대경로 \
  --brief /tmp/pstack-요청-a.txt \
  --report /tmp/pstack-결과-a.md \
  --read-only --dry-run
```

`--name`은 `hc`가 허용하는 영문 소문자·숫자·`-`·`_` 1~32자로 정한다. 실행 미리보기로 경로·역할·명령을 확인한 뒤 `--dry-run`을 빼서 실행한다. 비교·리뷰에서 특정 도구를 직접 지정할 때는 `--agent claude`, `--agent antigravity`, `--agent codex`를 쓴다. 스크립트는 안티그래비티에 항상 `--dangerously-skip-permissions`를, 새 Codex에 `--no-daemon`을 붙인다.

현재 터미널임을 대조한 주소가 있으면 `--parent <터미널>`을 추가한다. 주소를 확인하지 못했으면 생략한다. 이때는 잘못된 부모에게 연결하지 않도록 `--no-parent`로 실행하며, 총괄이 생성 응답의 주소로 직접 기다리고 결과를 수집한다. 현재 부모 주소는 실행 담당이 자의적으로 추측하지 않는다.

스크립트는 `hc run --bg`로 대화형 CLI를 실행하며 `--print`·`-p` 모드를 사용하지 않는다. 이름은 같은 작업의 다른 실행과 겹치지 않게 정한다. 실패·시간 초과 시 먼저 해당 실행을 조회하고 중복 요청을 만들지 않는다.

`--read-only`는 작업 요청의 제한이다. OS 수준의 읽기 전용 격리를 제공하지 않는다. 요청한 보고 파일 외에 프로젝트를 변경하지 말라고 전달하고, 총괄은 작업 전후의 해당 저장소 `git status`·diff를 확인한다.

변경을 병렬로 맡길 때 같은 파일·같은 Git 인덱스를 공유하지 않는다. 기존 프로젝트 규칙이 워크트리를 금지하면 임의로 만들지 않는다. 독립 임시 경로에 변경안만 받고 총괄이 반영하거나, 겹치는 변경을 순서대로 처리한다.

## 전달·대기·취합

1. 생성 응답의 실제 터미널 주소로 `hc get`·`hc read`를 실행한다. 생성 응답만으로 첫 요청 전달과 작업 시작을 단정하지 않는다. 응답에 `first_message.sent: false`가 있으면 준비 상태를 확인한 뒤 한 번만 전달한다.
2. 안티그래비티는 위 욜로 옵션을 붙여 시작한다. 추가 인증·신뢰 화면이 나오면 내용을 확인하며, 다른 도구의 권한 설정을 임의로 바꾸지 않는다.
3. `hc wait <터미널> --timeout 45`로 기다린다. `timeout`이면 작업 상태를 확인하고 다시 기다린다. `message`이면 전달된 보고를 읽는다. `blocked`·`error`이면 `hc get`·`hc read`로 이유를 확인하고, 할당량 문제라면 [대체 실행 절차](#할당량-조회와-대체-실행)를 따른다.
4. 보고 파일을 직접 읽고 필요한 코드·diff·실행 근거와 대조한다. `idle`·`done` 표시나 파일 존재만으로 내용 검증을 대신하지 않는다.
5. 읽기 전용 작업은 변경 여부도 확인한다. 결과는 채택·추가 확인·제외로 판단하며 중복 지적은 합친다.
6. 새 작업은 새 실행 담당에게 맡긴다. 기존 프로세스나 미커밋 변경 등 옮기기 어려운 상태가 꼭 필요한 경우에만 재사용한다.
7. 본인이 만든 숨은 실행은 결과를 받은 뒤 정리한다. 사용자가 볼 새 패널을 요청한 경우에는 남겨두며, 기존 사용자 터미널은 닫지 않는다.

## 보이는 패널

일반 위임은 `hc`의 자식 실행으로 한다. 사용자가 새 옆 패널을 요청하면 `herdr-app ls`에서 확인한 현재 패널의 오른쪽에 `pane.split`을 실행한다. 작업 폴더와 초기 요청을 포함한 실제 CLI 인자를 JSON 배열로 전달한다. `--dry-run` 출력의 `program_argv`는 해당 배열을 준비할 때 참고할 수 있다.

`pane.split` 응답의 패널·터미널 주소를 사용한다. 생성 후 앱 목록과 `hc get`·`hc read`로 실행을 확인한다. `hc`로 이미 시작한 담당을 보이게 할 때는 `terminal.keep`을 사용하며 같은 담당을 다시 시작하지 않는다. 실행·배치 문법은 항상 현재 `herdr-app commands`를 우선한다.

## Cursor 기능과 저장 경로

| 원본 기능·경로 | 이 환경의 처리 |
| --- | --- |
| `AskQuestion`·할 일 도구 | 현재 제공되는 질문·계획 도구. 없으면 한국어로 직접 정리 |
| `poteto-agent`·`comment-sicko` | 해당 원본 지시 파일을 자식 요청에 절대 경로로 전달 |
| `.cursor/skills/verify-*` | 프로젝트 `.agents/skills/verify-*`. 자체 스킬의 원본 관리·배포 규칙도 함께 준수 |
| `~/.cursor/rules/pstack-models.mdc` | 이 문서의 역할 표와 현재 요청의 명시적 모델 선택. `.mdc` 파일을 만들지 않음 |
| 과거 Cursor 대화 경로 | 실제로 사용한 Codex·Claude Code·안티그래비티 기록. 접근·출처를 확인한 것만 사용 |
| Cursor Cloud Agents | 허용된 로컬 자식 실행. 클라우드 전용 머신·상태는 대체됐다고 주장하지 않음 |
| Cursor Automations·Benny | 전용 실행 환경이 없어 미지원으로 표시. 자동으로 다른 서비스에 등록하지 않음 |
| Bugbot 시작·설정 | 제공되지 않으면 생략 표시. 이미 있는 PR 댓글은 접근 가능한 GitHub 도구로 확인 가능 |
| PR 생성·댓글·병합 | 현재 프로젝트의 Git 정책과 사용자에게 받은 권한 범위에 따라 실행. 스킬 설치만으로 승인된 것으로 보지 않음 |

브라우저 검증은 프로젝트의 기존 검증 도구와 현재 브라우저 사용 지침을 따른다. 별도 의존성이나 서버를 임의로 설치하지 않는다. 형식 검증 도구·영상 생성·웹훅 등이 필요한 작업은 실제 도구와 권한을 확인하고, 없으면 누락된 검증을 명시한다.

## 설치와 갱신

이 커스텀 스킬의 정본은 이 저장소의 `skills/poteto-mode/`다. `config/local-skills.txt`에만 등록하며 전역 배포 목록에는 넣지 않는다. 프로젝트 적용은 정본의 `scripts/sync_project.py --project /프로젝트/절대경로`로 한다.

기존 프로젝트의 8개 개별 스킬은 보존한다. 이 모드가 실행할 때만 함께 제공한 최신 묶음으로 하위 스킬을 해석한다. 외부 원본 버전·커밋·파일 해시는 `manifest.json`에 있다.
