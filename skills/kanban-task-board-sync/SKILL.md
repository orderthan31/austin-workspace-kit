# Kanban Task Board Sync

## 목적

구현계획 문서의 atomic task를 Markdown/Obsidian 칸반 보드와 같은 상태로 맞춘다.

프로젝트가 `plan.md`가 아닌 다른 구현계획 파일을 쓰면 그 파일을 기준으로 한다.

## 기본 컬럼

| 컬럼 | 의미 |
|---|---|
| 접수됨 | 새로 추가된 태스크 |
| 진행중 | 현재 작업 중인 태스크 |
| 완료 | 구현과 검증이 끝난 태스크 |
| 폐기 | 현행 기획과 맞지 않아 취소된 태스크 |
| 보류 | 외부 결정, API, 디자인, 권한이 필요해 당장 진행하지 않는 태스크 |

## 작업 순서

1. 구현계획 문서의 태스크 목록을 읽는다.
2. 새 태스크를 `접수됨`에 추가한다.
3. 완료된 태스크를 `완료`로 옮긴다.
4. 취소선 처리된 태스크를 `폐기`로 옮긴다.
5. 태스크 이름이 바뀐 경우 기존 카드를 중복 생성하지 않고 수정한다.
6. 보드와 구현계획 문서의 ID가 일치하는지 확인한다.

## 카드 작성 기준

카드는 짧고 구체적이어야 한다.

좋은 예:

- `T132 결제 모달 닫기 이벤트 수정`
- `T133 사용자 목록 필터 상태 유지`
- `T134 대시보드 카드 로딩 상태 추가`

나쁜 예:

- `화면 수정`
- `화면 개선`
- `버그 고침`

## 주의사항

- 사용자가 구현계획 문서는 건드리지 말라고 하면 칸반도 보류한다.
- 폐기된 태스크는 삭제보다 `폐기` 컬럼 이동을 우선한다.
- 단, 사용자가 “이번 건은 체크 돌기 전이니 삭제하고 덮어써”라고 하면 취소선 없이 재작성할 수 있다.
- 프로젝트마다 컬럼명이 다를 수 있으므로 기존 보드의 컬럼명을 먼저 읽고 맞춘다.
